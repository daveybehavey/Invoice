# NoteBill Paid Boundary V1

Updated: May 19, 2026
Status: recommended product boundary for the current release stage

## Goal

Make the first paid boundary feel fair, easy to explain, and tightly connected to real value.

The user should feel:

- free is enough to trust the app
- paid is for repeated workflow value
- nothing critical to money safety is locked away

## Recommended V1 Boundary

### Free should include

- create invoices from Billie, scratchpad, import, or manual editor
- review and edit invoice details
- export PDF
- open existing saved invoices
- basic guest-mode usage
- a limited number of new saved invoices per month

### Pro should unlock

- more or unlimited saved invoices
- account-tied sync and entitlement continuity
- send invoice from NoteBill
- reminder workflow
- hosted payment links
- client portal handoff
- saved client memory
- saved service memory
- repeat-work shortcuts and faster invoice-again loops

## What Should Not Be Paywalled

These should stay available because locking them would damage trust:

- invoice review/editing
- export PDF
- access to already-saved invoices
- basic transparency about totals, dates, and line items
- support/contact path

## Why This Boundary Fits NoteBill

Users are not paying for raw AI output.

They are paying when NoteBill becomes the full invoice operations loop:

- save it
- send it
- follow up
- get paid
- reuse what worked next time

That means the paid line should sit around workflow continuity and payment collection, not around first-draft creation.

## Current Product Language To Support

The simplest positioning for this boundary is:

- Free: draft, review, export
- Pro: save more, send, remind, get paid, reuse

That wording is close to what the app now communicates in the launcher and plan surfaces.

## Recommended Near-Term Pricing Shape

Do not lock this publicly until payment proof and early-user reactions are stronger, but the clean current recommendation is:

- Free
- Pro monthly around `$19/month`
- Lifetime optional as a one-and-done offer for people who know they will keep using it

If you want the simplest launch message:

- "Monthly if you want ongoing access"
- "Lifetime if you want to pay once and keep NoteBill"

If pricing changes later, this boundary can still stay mostly the same.

## What To Validate Next

Before pushing harder on monetization, confirm:

1. one clean Android Google Play subscription unlock
2. one clean Android lifetime unlock
3. one real invoice send from the library UI
4. at least a few real users reach the free save limit after genuine usage

## Product Rule

If a user cannot yet trust NoteBill with one real invoice, it is too early to push payment friction harder.

If a user already trusts NoteBill with repeated invoice work, Pro should feel obvious.
