# Apple App Store Screenshot Storyboard

Goal: turn the current mobile product into a clean App Store story that explains the wedge in a few screenshots.

## Story to tell

1. Paste rough notes
2. Billie drafts fast
3. You approve the money
4. Send the invoice
5. Keep statements and follow-up organized
6. Reuse repeat work faster next time

## Recommended screenshot set

Use 5 to 7 screenshots. The strongest default set is:

### Screenshot 1: Launcher / entry

Headline copy:
- `Billie drafts fast. You approve the money.`

Callout:
- `Quick AI invoice`

Purpose:
- immediately explain the product wedge

### Screenshot 2: Quick AI invoice

Headline copy:
- `Paste rough notes. Get a draft fast.`

Callout:
- `Generate draft`

Purpose:
- show the fastest path from notes to draft

### Screenshot 3: Draft review

Headline copy:
- `Review the money before you send.`

Callout:
- `Needs a choice` or `Ready to generate`

Purpose:
- show control and trust

### Screenshot 4: Send-ready state

Headline copy:
- `Send a clean invoice or PDF handoff.`

Callout:
- `Send` or `Export PDF`

Purpose:
- show the finish line

### Screenshot 5: Client statements and follow-up

Headline copy:
- `Keep statements and follow-up organized.`

Callout:
- `Email statement` / `Copy follow-up` / `Print statement`

Purpose:
- show the collections wedge

### Screenshot 6: Repeat-work / library reuse

Headline copy:
- `Reuse repeat work faster next time.`

Callout:
- `Open saved invoice`

Purpose:
- show retention value

### Screenshot 7: Trust / FAQ

Headline copy:
- `Why not just use ChatGPT?`

Callout:
- short answer that NoteBill is a workflow, not a generic chat tool

Purpose:
- answer the biggest objection before users bounce

## Copy rules

1. Keep each screenshot to one idea.
2. Keep the headline short.
3. Use the same language we use on the site:
   - Billie drafts fast
   - you approve the money
   - statements
   - follow-up
   - repeat work
4. Avoid screenshots that need a lot of explanation.

## Visual rules

1. Prioritize mobile-first framing.
2. Keep the main action visible.
3. Avoid cramped bottom-sheet overlays.
4. Avoid showing debug-like or unfinished states.
5. Favor calm spacing and clear hierarchy over feature density.

## Recommended final order

If you only do five screenshots, use:

1. Launcher / entry
2. Quick AI invoice
3. Draft review
4. Send-ready state
5. Client statements and follow-up

If you do seven, add:

6. Repeat-work / library reuse
7. Trust / FAQ

## Best-practice note

The first screenshot should not feel like a dashboard.
It should feel like a shortcut.
